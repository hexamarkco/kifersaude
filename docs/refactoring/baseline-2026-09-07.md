# Baseline da refatoração estrutural

Registro coletado antes das mudanças arquiteturais. Ele serve para distinguir dívida
preexistente de regressões introduzidas durante a refatoração.

## Verificações

- `npm test`: 51 arquivos e 347 testes aprovados.
- `npm run build`: aprovado; maior chunk `vendor` com cerca de 650 kB.
- `npm run migrations:check`: aprovado.
- `npm run audit:visual`: aprovado, com 22 ocorrências conhecidas em três arquivos.
- `npm run typecheck`: quatro erros preexistentes de inferência dos IDs de tabs em
  `SystemSettingsScreen.tsx`.
- `npm run lint`: dois erros `prefer-const` e 24 warnings preexistentes.

Os seis erros bloqueantes acima são corrigidos no primeiro commit. Warnings serão
tratados ao tocar nos módulos correspondentes; eles não serão ocultados por novos
disables.

## Hotspots iniciais

- `WhatsAppInboxScreen.tsx`: mais de 12 mil linhas, 146 estados e múltiplos fluxos
  de dados, realtime, mídia, IA e renderização no mesmo componente.
- `leads-api/index.ts`: mais de 5 mil linhas.
- `comm-whatsapp-campaign-worker/index.ts`: cerca de 3,7 mil linhas.
- `_shared/comm-whatsapp.ts`: mais de 4 mil linhas.
- `AutoContactFlowSettingsScreen.tsx`: cerca de 3,8 mil linhas.
- `ContractForm.tsx`, `LeadsManagerScreen.tsx` e `DashboardScreen.tsx`: mais de
  2 mil linhas cada.
- `src/lib/supabase.ts`: cliente/infraestrutura e tipos de vários domínios no mesmo
  módulo, importado por aproximadamente 90 arquivos.

## Regras do baseline

- Migrations históricas são imutáveis.
- URLs, payloads e comportamento observável permanecem compatíveis.
- Um commit de refatoração só é aceito depois dos gates aplicáveis ficarem verdes.
- Comportamentos duvidosos são preservados e registrados no relatório final.
